# 任务与 Avatar 对话系统重设计说明

## 背景与目标

本次重设计将实验任务、非目标问题题库和 Avatar 对话节奏统一到同一套可追踪的数据模型中，解决原实现将问题次数硬限制为 `1` 的错误，并确保同一任务内已经出现的问题不会再次出现。

设计目标如下：

- 每个任务拥有独立、可配置的非目标问题题库。
- 非目标问题按稳定且可复现的规则触发。
- 同一任务内不重复询问已经出现的问题。
- 对话流式与非流式路径使用一致的提示词和节奏决策。
- 对每次触发决策保留可审计的运行数据。
- Avatar 不获取参与者私有目标，也不主动推进参与者尚未提及的交易步骤。

## 任务与问题题库

`ExperimentTaskCatalog` 中的 `NonGoalQuestionDefinition` 现在是正式任务数据。当前 7 个任务各配置 3 个非目标问题，共 21 个问题，并为每个问题分配全局唯一 ID。

问题 ID 用于选择、去重、历史恢复和实验日志记录。运行时只接受当前任务中 ID 非空且唯一的问题，避免重复配置影响实际次数上限。

## 触发次数与题库上限

运行配置中的 `maxNonGoalQuestionsPerTask` 表示期望的最大触发次数，当前配置值为 `3`。它不是脱离题库大小的固定硬限制。

每个任务的实际硬上限为：

```text
min(maxNonGoalQuestionsPerTask, 当前任务有效且唯一的问题数量)
```

因此，当题库有 3 个有效问题且配置上限为 3 时，最多可触发 3 次；当题库更小时，实际次数自动缩小到题库大小。原先将实际硬上限固定为 `1` 的逻辑已移除。

## 随机决策与问题去重

Avatar 对话节奏使用稳定的 FNV 哈希生成随机样本。该随机决策与语言模型的采样参数分离，不依赖 LLM 的模型采样温度。

当前 Avatar 节奏配置字段 `temperature` 为 `0.7`，在此模块中表示触发阈值，不会写入 LLM 请求作为模型采样温度。每次生成回复前，系统基于当前会话、任务和消息上下文计算一次节奏决策，并从尚未出现的问题中选择唯一问题。

已经出现的问题 ID 存入 `HashSet`。选择候选问题时会排除集合内的 ID，因此同一任务内的问题不会重复出现。当所有有效问题均已出现，或达到实际硬上限后，不再触发新问题。

## 会话状态与历史恢复

节奏状态按当前会话和任务维护：

- 开始新会话或切换任务时，清空已问问题和相关计数。
- 恢复历史对话时，从已保存的节奏数据恢复出现过的问题 ID。
- 恢复后继续排除这些问题，防止重新进入会话后重复询问。

这使实时对话和恢复后的对话遵循同一套次数与去重约束。

## Avatar 行为边界

Avatar 只根据公开任务场景、对话历史和参与者当前表达进行回应，不接收参与者的私有任务目标。提示词明确限制 Avatar 不得主动推进参与者尚未提及的交易步骤，也不得虚构任务细节。

当本轮触发非目标问题时：

- 只允许使用节奏决策指定的一个问题。
- 指定问题必须逐字放在回复最后。
- 回复主体仍需自然回应参与者当前话题。

当本轮未触发时：

- 回复中禁止使用问句。
- 不得索取额外信息。
- 不得自行补充或虚构任务细节。

流式和非流式生成路径共享同一套提示词构建与节奏决策，避免两种输出方式出现行为差异。

## 运行记录与可审计性

每次对话请求都会在 payload 中写入 `AvatarDialoguePacingData`，并将以下字段记录到 CSV：

- `triggered`：本轮是否触发非目标问题。
- `questionId`：触发的问题 ID；未触发时为空。
- `temperature`：本轮使用的 Avatar 节奏触发阈值。
- `randomSample`：稳定哈希产生的随机样本。

这些数据可以用于复现实验行为，并核对问题触发、去重和模型参数是否符合配置。

## 保持不变的范围

本次没有重设计以下流程：

- 固定开场内容。
- 目标完成评估器。
- 参与者任务面板。
- 纠错内容的播放顺序。

这些模块继续沿用现有实现，仅通过新的任务目录和对话节奏数据与 Avatar 回复流程协作。
